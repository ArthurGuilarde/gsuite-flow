# Validation
`python scripts/validate.py` runs CLI documentation parity, ruff lint/format, mypy on `src/` and the unit tests with a coverage floor (`fail_under` in pyproject.toml). `--integration` additionally exercises a real disposable PostgreSQL instance with separate owner and runtime connections. Environment variables: TEST_MIGRATION_DATABASE_URL and TEST_DATABASE_URL. Runtime username must be guilarde_app. Integration setup may create that role and migrate the disposable database; tests create and drop a dedicated tenant_test_records table and truncate it along with sessions. The test table uses separate metadata and is never part of the production migrations. Never use production URLs.
Unit checks cover signature, algorithm, audience, issuer, expiry, future iat, malformed Core grants, Core failure, mismatched authorization identities, access/read/write, CSRF, mandatory tenant, no-store, exclusive bootstrap, bootstrap personalization and the read-only `bootstrap.py --check` (which never echoes `.env` values).
PostgreSQL checks cover unfiltered SELECT isolation, INSERT/UPDATE WITH CHECK, UPDATE/DELETE of another tenant, missing context, connection reuse, rollback, shared-workspace visibility, runtime privileges and authorized HTTP CRUD. SQLite substitutes cannot validate RLS.
OIDC provider interoperability, proxy TLS behavior and real Core membership revocation need staging checks; mocked authorization tests alone are insufficient.
CI requires integration URLs, audits requirements.lock with pip-audit, builds the production image and scans it with Trivy (commit-pinned action; fixed HIGH/CRITICAL findings fail). Runtime dependencies are pinned in requirements.lock and installed by Docker/CI. Update with pip-compile and rerun all checks.


Local development additionally exercises `python -m src --profile dev`, migrate/check, the real loopback HTTP login, CSRF, opaque cookies, fixture grants and tenant changes against a temporary SQLite file. Failure cases ensure production rejects SQLite/local auth and requires separate migration credentials. Container tests read the Dockerfile `CMD` and compose `command`, require both to start through the profiled CLI, and run the Dockerfile command to prove it refuses owner credentials. CLI documentation parity and startup log safety are checked automatically. SQLite checks cover ORM guardrails, not PostgreSQL RLS.


CI also validates installation and the local development suite on Windows with Python 3.12. requirements.lock keeps uvloop excluded on Windows and pins Windows timezone data for psycopg; preserve these platform markers when regenerating on Linux.
